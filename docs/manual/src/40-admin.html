Administration section

Device information

Shows the installed firmware version, the project name, the connected Wi-Fi network and IP address, the name of the setup access point (BatteryTester-XXXXXX), its address http://192.168.4.1, and whether the clock has been synchronised (HTTPS clock). System status shows the network message and leads to the update page.

Test run management

This table lists all runs in the SD database, 50 per page, newest first.

  • Filter: free-text Search (name, battery, plan, date, status or run ID), Battery, Status and a date range (From date / Through date; the end date includes the whole day). Click Apply filters; Reset filters clears them.
  • Rename: select one run with the radio button and click Rename. Up to 100 characters; an empty name restores the automatic name. The name is also used in the dashboard.
  • Delete: select a run and click Delete. After confirmation the run is permanently removed together with its measurements, segments and DCIR results. Batteries and plans are kept.

Running runs are protected and cannot be renamed or deleted. Renaming and deleting require the login password and only affect the SD database – existing MariaDB backups are not changed, and custom names are not transferred to MariaDB.

CautionDeleting cannot be undone. Make a backup (MariaDB synchronisation or a copy of the database file) before deleting important runs, and do not delete runs while a MariaDB synchronisation is running.

SD card

A simple file manager for the microSD card – no need to remove it from the device. The header shows whether a card is mounted and how much space is free.

  • Click a folder name to open it; use the breadcrumb path to go back.
  • New file, New folder and Upload files (several files possible, with progress bar).
  • For each entry: Download (files only), Rename, Move and Delete.

Deleting is permanent; only empty folders can be deleted. The card is never formatted automatically. The measurement database is the file ebc_a20.db in the root folder; download it regularly as a backup.

CautionDo not rename, move or delete the database file while the device is in use. Download it only when no test is being recorded to get a consistent copy.

Updates

When the device is connected to the Internet it checks for new firmware after connecting, every six hours and once each time you open the web interface. Only a small description file is downloaded – firmware is never installed automatically.

  1. If an update is available, the new version and its release notes are shown. Check for updates repeats the check manually.
  2. Make sure no test is running, then click Start update and confirm the version.
  3. The firmware is downloaded into the inactive memory area and checked (size and SHA-256 checksum). Progress is shown.
  4. After successful verification the device restarts. The new firmware is only accepted permanently if it runs stable for 10 seconds; otherwise the previous version is restored automatically.
WarningDo not disconnect the power during an update, and never update during a battery test.

A firmware update keeps all settings, including the FactoryModeMaker configuration, the passwords and the Wi-Fi credentials.

While the configuration is inactive, update checks are switched off; the tab is still shown.

Settings

The Settings tab collects all device settings. When you save a setting you are asked for the current login password (labelled Admin password in the dialog) as an extra protection – also when browser login is switched off. Cancelling or entering a wrong password does not save anything. The access-point password is not used here. On Maker devices this confirmation can be switched off in Maker Settings.

Changing the password or switching browser login on or off ends all existing sessions; the page reloads automatically. Afterwards log in with the new password.

WarningWith browser login switched off, everyone in the network can view all data and operate the tester – including starting and stopping tests. Use this only in a network you trust completely. Settings changes still require the login password.

Configure Wi-Fi

Network name (SSID) and password of your home network. Leave the password empty for an open network; otherwise 8–63 characters or 64 hexadecimal characters. The credentials are stored on the device.

EBC tester

Selection of the tester model – see Selecting the tester model.

Home Assistant MQTT

Optional connection to an MQTT broker, typically the one used by Home Assistant. The device then appears automatically in Home Assistant (MQTT discovery) and publishes voltage, current and capacity of every recorded measurement.

Enable MQTTSwitches the client on or off.
Broker host / portIP address or host name (without mqtt://), port usually 1883.
User name / passwordBroker account. Leave the password empty to keep the saved one.
Topic prefixStart of all topics, for example ebctester.
Measurement expiry interval (s)Interval between recorded measurements; values become "unavailable" after three intervals without new data.
Allow remote plan start commandsOff by default. Only when enabled can a plan be started via MQTT. Stop and Abort always work.

Save settings applies the settings immediately, Test connection reconnects with the saved settings. The connection state is shown below. MQTT is unencrypted – use a dedicated broker user with restricted rights. Details are given in Home Assistant MQTT topics.

MariaDB backup

Copies the recorded test runs to a MariaDB database, for example on a NAS. Only new data is transferred; repeated or interrupted synchronisations do not create duplicates.

  • Enter server, port (3306), database, user and password; choose Automatic backup and an interval in minutes (0 = manual only). Save.
  • Test connection checks access, Sync now starts a transfer immediately, Transfer everything again re-sends all data (no duplicates are created).
  • The status area shows state, last successful backup, number of runs and measurements transferred, and the server version.

Automatic backup only runs with Wi-Fi, a ready SD card and a saved password. Runs deleted on the device remain in MariaDB. The database tables must already exist on the server – see MariaDB backup database. The connection is unencrypted: use it only in your home network.

Debug log

When enabled, the device keeps the last 500 log lines in memory and shows them in the Debug tab. Disabled by default; disabling frees the memory. Logging never delays recording, plans or SD access.

Language

English and German are built in. Additional languages can be added as JSON files in the folder /languages on the SD card (see Appendix A). Reload languages reads the folder again; then select the language in the header.

Device reset

Two reset functions return the device to the state of its first start. Both ask for confirmation and the login password, restart the device and detect the mode (GPIO 47) again. Data on the SD card – measurements, batteries, plans and language files – is never erased.

ButtonResetsKeeps
Reset device configurationDevice configuration (all Maker Settings and ConfigAktive), login password (back to ebctester), login options, access-point password, Firmware mode Wi-Fi credentials, tester model, current battery and plan, MQTT and MariaDB settings, debug-log setting
Erase all NVS settings including Wi-FiEverything stored on the device, including Wi-Fi credentials, tester model and all service settings Only the firmware and the SD card

A reset is refused while a test, plan or recording is running or a firmware update is in progress. Stop the test and wait until the recording has finished.

NoteOn an original board in its delivered state, the device starts in FactoryMode again after a reset and is immediately ready for use. If JP1 has been changed, the device starts in MakerMode and has to be configured (see the Maker Edition of this manual).
NoteAfter a reset, Maker devices start inactive again with the default pin assignment of the firmware. Note your Maker Settings before resetting.

Maker Settings

On an active Maker device, Maker Settings is the last tab of the Administration section. It contains the same form as during the first setup (see Maker Settings reference). Every save restarts the device.

Debug

Live log of the running firmware – useful when something does not work and no USB cable is at hand. Pause freezes the display, Clear buffer empties it, Download saves the lines as a text file, and Follow output keeps the view at the newest line. Log lines may contain network and file names, but never passwords. Messages from the very beginning of the start-up – including the mode detection – are only visible on the USB console.
