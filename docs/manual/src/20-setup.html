Setting up

Connecting the hardware

The connectors are on the edges of the board: J4 for the tester at the bottom of the right edge, the expansion connector J3 above it, the microSD socket J1 at the top left and the USB-C socket J2 on the left edge. The LEDs are on the left side, the BOOT and RESET buttons in the bottom left corner and the CR2032 holder in the middle. The antenna socket (u.FL) is on the ESP32 module U4 at the top of the board.

  1. Antenna. Mount the SMA socket of the antenna cable in the housing, plug its small u.FL plug onto the socket of the ESP32 module and screw on the antenna. Without an antenna Wi-Fi does not work.
  2. microSD card. Insert a FAT32-formatted card. The card is never formatted automatically; a new, empty database is created on it at first use.
  3. Tester connection. Connect J4 to the tester's serial interface (pin assignment in Connectors). The board's TX line goes to the tester's RX line and vice versa. With the EBC-A20, J4 can also supply the board from the tester's 19 V adapter.
  4. Power. Power the board either through J4 (19 V) or through USB-C. Both may be connected at the same time.
CautionThe pin order of the cable on the tester side differs between tester models (the EBC-A40L uses a different connector, and TX/RX have been reported swapped compared with the A20 cable). Check the pinout with a multimeter before connecting. The A40L and A50L are mains-powered and do not supply 19 V – power the board through USB-C in that case.
NoteLeave solder jumper JP1 in its delivered state (pads 1–2 bridged). It tells the firmware that it runs on an original board. Changing it has an effect only after a device reset and turns the device into a Maker device that has to be configured by hand.

Building and first start

Hardware requirements

The firmware does not depend on a particular board. All pins are configured in the browser after the first start. Your hardware must, however, meet the following requirements:

ItemRequirement
MicrocontrollerESP32-S3 with 16 MB flash. Octal PSRAM (N16R8) is optional but recommended. Modules with the "U" suffix need an external 2.4 GHz antenna.
Tester UARTOne TX and one RX pin, connected through a 3.3 V ↔ 5 V level shifter (for example TXS0104E) to the tester's TTL port. TX of the ESP32 goes to RX of the tester and vice versa.
Dongle UARTA second TX/RX pair is required by the configuration (reserved for a future PC dongle bridge). It can be left unconnected, but the pins must be free.
SD card4-bit SDMMC (CLK, CMD, D0–D3) or SPI (MISO, MOSI, CS, CLK); 10 kΩ pull-ups to 3.3 V on CMD and D0–D3 (SDMMC) or MISO/MOSI/CS (SPI). Card detect is optional and must be high when a card is inserted.
Status LEDOptional WS2812 (GRB) on any output-capable GPIO.
GPIO 47Leave it open or tie it to GND. A high level selects FactoryMode (see Factory and Maker devices).

The following pins cannot be used for the peripherals: GPIO 26–32 (internal flash), GPIO 33–37 (octal PSRAM), GPIO 19/20 (native USB), GPIO 43/44 (serial console). Avoid the strapping pins 0, 3, 45 and 46. Details are given in Pins and wiring rules.

TipThe original EBCTester board is a complete reference design. Its circuit, bill of materials and pin assignment are documented in Part II and can be copied for your own build.

Installing the firmware

Each GitHub release contains a file EBCTester-<version>-full-install.bin with bootloader, partition table and application. Flash it once over USB at address 0x0, for example with Espressif's esptool:

esptool.py --chip esp32s3 --port COM5 write_flash 0x0 EBCTester-1.99.3-full-install.bin

If the board is not recognised, start it in download mode: hold BOOT, press and release RESET, release BOOT. Later updates are installed over Wi-Fi (see Updates). To build the firmware yourself, see Building from source.

NoteRelease images contain no pin assignment that you would have to match: on a Maker device the hardware configuration is entered in the browser. The values offered at the first start are the defaults of the original board.

First start and login

At the first start the firmware samples GPIO 47 and, with the pin low or open, selects MakerMode with an inactive configuration. No UART, SD card, LED or other hardware output is driven; only the Wi-Fi access point and the web interface run.

On first start the device opens its own Wi-Fi access point. Its name is BatteryTester-XXXXXX, where XXXXXX is unique to the device. EBCTester uses two separate passwords:

PasswordUsed forInitial value
Access-point passwordConnecting to the Wi-Fi network BatteryTester-XXXXXX Set when the firmware was built; the standard firmware uses ebctester. If the firmware was built without one, a random password is generated at the first start and shown in the start-up log. Can be changed in Maker Settings.
Login passwordLogging in to the web interface (user admin) and confirming every settings change ebctester

To read a generated access-point password, connect the device to a PC by USB-C, open a serial terminal (for example the ESP-IDF monitor or PuTTY) and press RESET. The line Generated setup AP password shows the password; it stays the same after restarts.

  1. Connect your phone or PC to the Wi-Fi network BatteryTester-XXXXXX using the access-point password.
  2. Open http://192.168.4.1 in the browser.
  3. Log in with user name admin and the login password – on a new device ebctester. The login page labels this field Admin password.
  4. Change the login password right away under Administration → Settings → Login Settings or in Maker Settings (see Login Settings).
Cautionebctester is the same on every device and is published in this manual. Change it on first use. A device reset (see Device reset) restores this initial password.

A login is valid for 24 hours or 7 days, depending on the setting. It is not extended by activity and ends when the device restarts or you click Log out. Running tests and recording are not affected by logging in or out. The login can also be switched off completely (see Login Settings).

Configuring and activating the hardware

While the configuration is inactive, the web interface shows only three tabs: Maker Settings (opened first), Settings and Device information, plus Updates and – if enabled – Debug. The Battery tester section is not available yet.

  1. Open Maker Settings and enter the GPIO numbers of your wiring: tester UART, dongle UART, SD bus and its pins, card detect and the status LED. Use -1 for pins that are not connected. All fields are described in Maker Settings reference.
  2. Set a personal access-point password and web (login) password. Leave the password fields empty to keep the current passwords.
  3. Review the network and update options (time server, firmware manifest URL) and the recording settings.
  4. Tick Configuration active (ConfigAktive).
  5. Click Save and restart, confirm the restart and enter the current login password in the confirmation dialog.
  6. The device checks the configuration and restarts. Reconnect to the access point if necessary and log in again. The full interface with the Battery tester section is now available.

When the configuration is saved with ConfigAktive ticked, the firmware checks that every required pin is a valid, output-capable GPIO, that no pin is used twice and that no reserved pin (flash, PSRAM, USB, console) is used. If a check fails, nothing is saved and the message Invalid configuration. Check passwords, GPIO assignments, reserved pins and selected SD bus. is shown.

TipYou can save the configuration without ticking ConfigAktive. The device then restarts and stays inactive – useful to store passwords and Wi-Fi credentials before the wiring is finished.
CautionSaving the hardware configuration is blocked while a test, plan or recording is running or a firmware update is in progress. Stop the test and wait until the recording has finished first.

Connecting to your home Wi-Fi (optional)

EBCTester works completely without home Wi-Fi. Connecting it to your network is still useful: you can reach it from every device in the house, the clock is synchronised from the Internet (needed for correct date/time stamps and for update checks) and optional services such as MariaDB and MQTT become possible.

  1. Go to Administration → Settings → Configure Wi-Fi.
  2. Enter the network name (SSID) and password and click Save. Confirm with the login password when asked.
  3. The device connects; its new IP address is shown under Device information → Wi-Fi IP. Your router also lists it.

The protected access point remains active as a fallback, so you can always reach the device at http://192.168.4.1, even when the home network is out of range. Changing the Wi-Fi channel may briefly interrupt the access-point connection.

NoteWhile the configuration is inactive, the device runs the access point only. Wi-Fi credentials can already be saved; the device connects to your network after the configuration has been activated.

Selecting the tester model

Before the first connection you must tell EBCTester which tester you use – there is no default. Go to Administration → Settings → EBC tester, select the model and click Save tester model.

The selected model and its limits apply immediately, even without a connected tester, so you can prepare plans and parameters in advance. The model can only be changed while no operation, plan or recording is active. If the connected tester reports a different supported model, EBCTester shows an error, disconnects and does not reconnect automatically until you correct the selection or click Connect again.

Numeric input fields are checked as soon as you leave them. A red message below the field explains the allowed range; start and save buttons stay disabled until all fields are valid. When a start button is disabled for another reason (for example tester not connected), a yellow note below it tells you why.
